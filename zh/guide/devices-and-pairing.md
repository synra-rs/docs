# 设备与配对

设备可见、已配对和当前可达是不同事实。

## 设备状态

| 状态 | 含义 |
| --- | --- |
| 附近设备 | 最近收到发现公告，仍可能需要配对 |
| 已配对 | 配对流程已记录明确同意的关系 |
| 在线 | 近期发现或有效会话表明当前可达 |
| 已阻止 | 本机策略拒绝该设备及后续连接 |

已配对设备离线后仍保留配对。单独保存一个旧地址不能证明在线。

## 配对步骤

1. A 向 B 发起配对。
2. A 显示六位码并等待，B 显示同一个码及请求方名称。
3. A 可以取消；B 可以同意、拒绝或拉黑。
4. 只有同意后，配对流程才继续并保存关系。
5. 两端显示结果。拒绝或取消不会授予可用配对。

提示在整个应用中显示，接收端打开其他页面也能回答。
若决定前配对码就消失，或两端状态不同，请更新两端宿主后重试。

::: warning 配对码的作用
配对码用于人工核对本次请求。当前明文 TCP 配对不交换共享加密密钥，也不提供密码学对端认证。
:::

## 忘记与拉黑

“忘记”移除本机保存的关系或阻止决定，后续连接需要重新配对。
拉黑拒绝当前请求及后续连接，不授予已配对状态。

移除前请检查设备详情。另一台设备保存的状态也可能需要检查；
不要假定本机删除会远程重置对方数据库。

## 离线设备

设备停止公告后，发现记录会过期；离线公告也会更新界面。
重新出现时，宿主使用当前公告的端点。地址变化或应用重启本身不要求重新配对。

## 配对与插件权限

配对不会安装插件、批准能力或同意所有后续操作。
插件仍需相应的安装、确认和启用状态；按会话控制的功能会另行询问目标设备。
