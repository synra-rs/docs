# 故障排查

先判断失败发生在发现、连接、配对、插件确认，还是业务执行阶段。

## 从宿主开始

保持两端运行，将移动端 Synra 切回前台，打开控制台或诊断。
记录两端版本，以及同一次操作附近的日志。

使用源码 CLI 时，还可以运行本机诊断：

```sh
synra doctor
synra --output json doctor
```

本机诊断成功不表示设备互通，也不证明插件原生效果。

## 设备无法互相发现

1. 确认可互通的同一网络。访客 Wi-Fi 隔离和 VPN 路由可能分开设备。
2. 防火墙允许 Synra 的 UDP 发现与 TCP 连接。
3. 两端分别扫描，比较查询与收到公告的日志。
4. 检查启用的网卡及接收端应用前台状态。

| 日志或结果 | 能证明 |
| --- | --- |
| `lan query` | 已发送发现查询 |
| `lan heard address:port` | 收到了携带 TCP 监听端点的公告 |
| TCP 连接建立 | 对应端点接受了连接 |
| 插件任务成功 | 对应业务操作完成 |

::: info 发现不是连接测试
出现 `lan heard` 不代表公告的 TCP 端口可达。
UDP 回包端点与公告的 TCP 监听端点承担不同职责。
:::

## 端口与连接拒绝

UDP 发现默认使用 **32101**。应用启动时选择 TCP 监听端口并通过公告告知对端；
daemon 默认使用 **47100**，拥有独立命令行选项。

请查看当前公告，并在防火墙允许应用，不要依赖固定的应用 TCP 端口。
对端拨号时的临时源端口不是它的监听端口。

连接拒绝，包括 Windows 错误 **10061**，表示 TCP 连接被拒绝。
检查接收端监听是否运行、当前端点是否正确。旧构建持续使用配对时保存的地址时，请更新两端宿主。

## 配对无法完成

两端应保持同一个码，直到接收端决定或请求结束。
检查拒绝、取消、阻止和超时。只有确实准备重新配对时，才移除过期的本机决定。

一端配对码闪过、另一端已显示配对，不是正常完成。
请在两端使用当前构建，并比较日志。

## 插件权限与页面

- 显示“无需权限”但尚待确认时，选择“允许运行”。
- 能力列出后仍需批准，批准不会启用一个已停用插件。
- 接收设备可能也需要安装插件，并单独同意本次请求。
- 插件页面无法返回时，使用 Android 的原生返回栏。
- 弹层阻止后续操作时，从重新打开的宿主复现，并在报告中写出“详情 → 同步 → 控制台”的路径。

## 更新与注册表安装

- 注册表安装需要配置源。源列表为空只是关闭了该功能，不是故障。
- 只有已配置的注册表仍在发布该插件时，“检查更新”才会报出新版本。
- 需要新增权限的自动更新不会在后台安装，而是等待人工决定。
- 由“未审阅”密钥签名的包仍需要你决定。信任以密钥为准，不以名称为准。
- 定时检查是例行请求。没有网络、注册表不可用和包已下架，在这里看起来一样；
  具体拒绝原因在手动检查时给出。

## 报告问题

提供宿主与插件版本、系统或 Android 兼容环境、操作步骤、首条错误和两端附近日志。
避免包含文件内容、令牌和签名密钥。
