# 插件

插件提供 Synra 的具体功能，应用负责安装、权限、生命周期和页面容器。

## 安装

### 从目录安装

“从目录安装”接收构建后的包目录或包文件。
宿主先校验实际的清单、组件、UI 归档，以及包中提供的签名，通过后才保存。

混合插件在同一清单下包含 Rust/Wasm 组件与 UI ZIP。

### 从注册表安装

注册表搜索按顺序查询“设置 → 插件与来源”中配置的源。
没有内置公共目录；源列表为空时，注册表安装不可用。

可以按名称或准确包标识搜索，打开结果后先预览再下载。
预览给出插件、版本、发布者、索引为该发布者列出的密钥、请求的权限和包大小。
安装执行与本地包相同的校验。

::: tip 配置源不等于信任
添加注册表，或在其中找到一个包，都不构成信任，也不授予任何能力。
发布者密钥和插件能力分别决定。
:::

## 发布者密钥

签名的包会记录签名所用的密钥。本机尚未审阅的密钥显示为“未审阅”，
插件列表会标记“发布者未受信任”。“发布者”页列出本机见过的所有密钥，并统计仍需决定的数量。

| 状态 | 含义 |
| --- | --- |
| 未审阅 | 有包以该密钥签名并通过校验；还没有人比对过它 |
| 已信任 | 你接受该密钥，用于该发布者今后的包 |
| 已撤销 | 你拒绝该密钥；已安装的插件仍可能运行 |

信任前，请把指纹与发布者提供的指纹逐位比对。
这个决定针对密钥而非显示名称：同名但不同密钥是另一个发布者。信任密钥仍不授予任何能力。

## 确认与启用

| 步骤 | 含义 |
| --- | --- |
| 安装 | 校验并保存包 |
| 确认 | 明确允许插件运行 |
| 授予能力 | 选择允许的操作与范围 |
| 启用 | 请求激活插件 |
| 打开 | 进入插件自己的页面 |

::: info 无需权限也需要确认
“无需权限”表示能力列表为空。尚待批准时请选择“允许运行”；
安装和启用开关不会自动批准插件。
:::

已有授权先以查看模式打开，修改时再编辑。新增能力不预选。
保存失败会保留草稿，便于排除原因后重试。

## 更新

“检查更新”向已配置的注册表询问某个已安装插件发布了什么。
结果给出新版本，以及所需权限与当前版本相同还是新增。
在确认“更新”之前不会安装任何东西。

后台每天为已安装插件检查一次。
“设置 → 插件与来源 → 插件更新”决定检查之后做什么：

| 策略 | 后台行为 |
| --- | --- |
| 手动检查 | 不发起后台请求；“检查更新”仍然可用 |
| 仅通知 | 检查并报告可用更新，不安装 |
| 同一主版本 | 安装通过校验、且主版本不变的更新 |
| 所有稳定版本 | 安装任何通过校验的稳定版本 |

自动安装刻意收得很窄：需要同一已信任发布者密钥、没有新增能力，且包已通过校验。
需要新权限的版本会等待人工决定。更新保留插件数据。

## 活动与限制

“最近调用”列出该插件在本机被允许和被拒绝的调用，含耗时，以及报告中可引用的追踪标识。
“清除历史”只删除这些记录，插件数据与权限不变。
保留天数在“设置 → 插件与来源 → 审计历史”中设置，并在下次启动时生效。

插件同时受内存、实例数、每秒调用数、单次调用时长、存储、打开的传输数、
事件、网络请求和文件操作等限制。超出限制会向该次调用返回结构化错误，
宿主和其他插件继续运行。

## 同步到设备

选择“同步到设备”，检查计划并选择已配对目标。
读取已安装插件需要目标可达。“需要插件文件”是计划结果，不表示离线设备已经接受传输。

接收的包仍经过安装校验。打开前，请检查接收端的确认、权限及启用状态。

## 打开与返回

桌面插件在独立窗口打开。Android 使用独立插件 Activity，具有原生返回栏和系统返回。
导航入口位于插件网页之外。

部分操作需要另一端单独同意本次请求。配对和静态授权不会代替对方作出这个决定。

## 停用与移除

停用会停止调用并保留保存的数据。

移除时可以选择如何处理保存的数据。准备重装时可选择保留数据；
以确认项为准，不要假定卸载必定删除或保留数据。
