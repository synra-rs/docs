# 常见问题

## 每个插件都需要 Rust 吗？

是。所有受支持包都包含 Rust/Wasm 组件；hybrid 额外增加页面。
纯 UI 包会被拒绝。

## 无权限插件为什么也需要批准？

空能力列表表示不请求额外能力，运行已安装代码仍是用户的明确决定。
请选择“允许运行”，再启用。

## 安装 JS 客户端会创建连接吗？

不会。`@synra/client` 只有声明，Synra 负责注入运行时客户端；
`@synra/testkit` 提供开发用模拟环境。

## 插件可以直接操作系统吗？

Wasm 使用宿主导入、能力检查及执行限制，
UI 使用注入客户端并遵守宿主浏览器策略。
清单声明和配对都不能绕过当前授权或必需的接收端决定。

## SDK 中的 API 在所有宿主都能用吗？

不能。需要检查宿主实现和平台支持。
例如，当前应用适配器明确拒绝安全存储和通用 headless device-send 导入，
鼠标会话使用另一条已实现的服务。

## 可以用设备名作为目标吗？

使用标准 UUID。名称用于显示，可能修改或重名。
发现结果为 `desktop` 的设备可以作为电脑候选，无需假定其具体系统。

## 离开页面后插件还能继续工作吗？

只有具备合适宿主生命周期的任务才能独立于页面继续。
交互式控制会在页面隐藏或关闭、权限变化及断连时结束。
移动端后台执行没有持续运行保证。

## 已配对连接是否加密？

当前设备通信使用明文 TCP。配对码是人工核对码，不是共享加密密钥。
请在可信局域网使用。

## 测试成功能证明什么？

见[测试](/zh/plugins/testing)。浏览器预览、真实组件、回环连接和实体平台效果是不同层次的证据。

## 在哪里报告问题？

插件行为在插件仓库反馈，页面承载和管理在应用仓库反馈，
内核、SDK 或作者工具在 core 仓库反馈。请提供版本和首条错误，避免私密数据。
