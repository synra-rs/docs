# 构建界面

插件的界面是一个 WebView 包，内核把它加载进一个隔离的上下文，并给它一个客户端对象。那个客户端就是页面
能触达的全部 —— 没有 `window.synra`、没有文件系统，也没有除插件声明之外的网络。

## 两类插件

| 运行时 | 内核加载什么 | 插件能做什么 |
| --- | --- | --- |
| `runtime.headless` | 一个 WebAssembly 组件 | SDK 暴露的一切 |
| `runtime.ui` | 一个 WebView 包 | 只有注入客户端暴露的那些 |
| 两者 | 两者，共用一份清单 | 两者，通过内核互相通信 |

::: info 只有界面的插件不只是更简单，而是更安全
内核不从它加载任何代码。它做的一切都经过客户端，而每一次客户端调用都是内核能归属、能限流、能拒绝的调用。
UI 插件无法活得比它所在的页面更久。
:::

## 注入的客户端

插件的页面通过**一个**全局对象触达宿主，它在页面自己的代码运行之前就已经存在。

| 命名空间 | 用来 |
| --- | --- |
| `env` | 环境事实：SDK 版本、语言、深色模式 |
| `log` | 写日志 |
| `event` | 发出与订阅事件 |
| `device` | 列出设备，以及触达其中一台 |
| `storage` | 插件自己保存的数据 |
| `network` | 插件声明过的请求 |
| `transfer` | 收发文件 |
| `platform` | 操作系统 |
| `clipboard` | 读写剪贴板 |
| `self` | 调用插件自己的动作 |

每个方法都是一次调用，所以返回 Promise。没有同步的东西 —— 同步调用就意味着让页面阻塞在内核上。

::: warning 客户端不是浏览器 API
没有 `fetch` 全局，也没有文件系统。用了其中一个的页面会在 WebView 里失败，而那个失败看起来会像插件的
bug，而不是宿主的拒绝。
:::

## 声明页面

UI 插件在清单里声明它的页面，内核从包里提供它们。

- **入口**是 WebView 加载的那个 HTML 文件。
- **默认页**是用户打开插件时落到的地方。
- 每个**页面**是插件让其可达的一条路由。

## 能力与界面

界面发出的调用，与 headless 插件的调用受完全一样的检查。一个调用了清单未声明之物的页面会拿到
`capability_denied`，而用户根本看不到关于它的提示。

::: tip 要得更少，安装提示就说得更多
`network:fetch:api.example.com` 和 `network:fetch:*` 在清单里只差一个词，在提示里差得很远。窄的那条告诉
用户：哪台服务器会看到他的数据。
:::

## 样式

页面是一个独立文档、独立 origin。宿主的样式表到不了这里，这里的样式也到不了宿主 —— 这同时意味着，
这里的一个 CSS reset 不会漏到应用的其他部分。

### 页面可以加载什么

页面显示的一切都来自包。它自身没有网络，所以一次指向字体服务、图标 CDN 或图床的请求就是一次失败 ——
而且它失败得很安静。

| 你想要 | 该怎么做 |
| --- | --- |
| 一个 Web 字体 | 把字体文件打进包、从包里提供：`font-src` 是 `self` |
| 一套图标 | 在构建期把图标打进包；运行期去取会渲染成一个空方块 |
| 一张远程图片 | 打进包，或者用 `synra.network` 取回来再渲染响应 |
| `fetch()` | `synra.network.fetch` —— 页面唯一的网络 |
| 一处内联样式 | 可以：`style-src` 允许 `unsafe-inline` |

::: warning 它的失败方式不是一个错误
取不到的字体会回落到系统字族，取不到的图标会渲染成一个空方块。两者看起来都不像宿主的拒绝，所以都会被
报成插件的 bug。需要什么就声明它，或者把它打进包。
:::

### 主题

`env` 报告环境，包括界面是否处于深色模式。宿主不会给你的页面加样式，所以这件事由页面自己做：
在你自己的根元素上设置主题，并让颜色由它驱动。

### 文字方向与语言

`env` 也带着语言。写 CSS 时用逻辑属性（`margin-inline-start`，而不是 `margin-left`），
这样从右到左的语言不需要第二份样式表；也不要把文字放进图片里。
